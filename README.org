* 说明

基于 [[https://github.com/iDvel/rime-ice][雾凇拼音 (rime-ice)]] 精简出来的个人 Rime 配置，只保留 **小鹤双拼** 一个方案，
并挂载 [[https://github.com/amzxyz/RIME-LMDG][万象语法模型]]（雾凇官方配方，参数为雾凇词库调校）。

两个结构性决定，详细理由见 =CLAUDE.md=：

1. **本仓库不带 =default.yaml=。** 底座固定为 Squirrel 出厂那份，所有偏离出厂的设定
   显式写在 =default.custom.yaml= 里。上游改自己的 =default.yaml= 影响不到本配置。
2. **定制一律走 =*.custom.yaml=，不改 vendored 文件。** 同步上游 = 直接覆盖，
   补丁自动存活，不需要逐条重放定制。

* 安装与部署

** 一、语法模型（必须单独下载，不在 git 里）

模型 401 MiB，超出 git 合理范围，已列入 =.gitignore=。每个部署目录各下一份：

#+begin_src shell
curl -L -o wanxiang-lts-zh-hans.gram \
  https://github.com/amzxyz/RIME-LMDG/releases/download/LTS/wanxiang-lts-zh-hans.gram
#+end_src

放在配置目录根下即可。当前使用版本的校验和：

: b4e1d9fd1bcdbe6c80f6c7d5fba2e99c236b09599f05f009a8317dbac1eada26

注意：上游 =LTS= 这个 tag 的附件是 **原地滚动更新** 的，按 tag 下载不保证内容一致。
两个部署目录的副本要保持同一份，换新版时两处一起换并更新上面的校验和。
（源仓库 =~/p/Rime= 不需要放 —— Rime 不读它，=rime_deployer --build= 也不加载语法模型。）

模型缺失时输入法仍可用，只是退化成没有语法模型的状态（长句排序变差）。

** 二、本机部署方式

本仓库在本机有两个 live 克隆：

- =~/Library/Rime= —— Squirrel（鼠须管）用户目录
- =~/.emacs.d/rime= —— emacs-rime 用户目录（=rime-user-data-dir= 默认值）

源仓库保持单提交历史（=git commit --amend=），所以克隆目录不用 =pull=，用 =fetch= + =reset --hard=：

#+begin_src shell
git fetch /Users/lakki/p/Rime master && git reset --hard FETCH_HEAD
#+end_src

=reset --hard= 不会动被忽略的未跟踪文件，所以 =.gram= 和用户词库不会丢。

⚠️ **永远不要在 live 克隆里跑 =git clean -xdf=** —— 它会把语法模型、自定义短语、
用户词库（=*.userdb/=）一起删掉。

然后重新部署：

- 鼠须管：=Squirrel --reload=
- emacs-rime：重启 Emacs 即可（librime 启动时自动增量部署）；也可以预构建，
  避免下次启动现场编译大词库：

#+begin_src shell
rime_deployer --build ~/.emacs.d/rime "/Library/Input Methods/Squirrel.app/Contents/SharedSupport"
#+end_src

部署后检查日志（=$TMPDIR/rime.squirrel/=）确认无 =E= 级错误。

** Unicode / 金额大写
- =U= + 十六进制码位：=U4e2d= → 中
- =R= + 数字：=R123.45= → 壹佰贰拾叁元肆角伍分（小键盘也能打，见键位表）

** UUID
输入 =uuid= 同时给出两个候选：
- **v7**（时间有序，排在前面）—— 本仓库独有的 =lua/uuid_v7.lua=
- **v4**（纯随机）—— 上游自带的 =lua/uuid.lua=

** 部件拆字反查
=uU= + 部件双拼，如 =uUmu= → 木。候选注释显示该字读音，适合查生字。

** 辅码筛选
打字过程中按 =`= 引导，再输入部件码筛选候选。按需触发，不打扰普通输入。
方案选单里的「正常／单字」开关（=search_single_char=）控制辅码查词时是否单字优先。

** 中英文混输
- 直接打英文字母给出英文候选（=melt_eng= 次翻译器）
- 中英混合词汇（=cn_en=）支持 =win10= 这类混排常用词
- =reduce_english_filter= 会把部分短单词往后压，避免抢占中文候选首位

** 长词优先（补回上游漏挂的）
=long_word_filter= 把较长的词往前提。输入 =jie= 原本是「1接 2解 3姐 …」，
长词「饥饿」「极恶」排在很后面；挂上之后提到第 4、5 位。

这个 lua 是雾凇自带的，而且雾凇在**全拼方案** =rime_ice.schema.yaml= 里就挂了它 ——
只是 7 个双拼方案 + t9 都没挂。所以本仓库通过 =double_pinyin_flypy.custom.yaml= 补回来，
挂载位置和参数（=count: 2=、=idx: 4=）都跟上游全拼方案一致：
=pin_cand_filter= 之后、=reduce_english_filter= 之前。

** 以词定字
输入编码把目标词高亮后，按 =[= 只上屏首字，=]= 只上屏尾字。
如打 =wego=（魏国）后按 =[= 上屏「魏」，按 =]= 上屏「国」。

** 自定义短语
编辑 =custom_phrase_double.txt=。

★ 格式是 **=候选词<Tab>编码<Tab>权重=** —— **词在前，编码在后**，别写反了。
写反不会报错，词条直接静默失效。权重可省略，同编码下数字越大越靠前。
编码可以随便起，不限于双拼。

#+begin_src text
工程	gc
打开	dk
name@example.com	yx
#+end_src

方案里 =custom_phrase/initial_quality: 99=，高于拼音和英文，所以这里写的词会顶到最前面。

** 自动调频与造词（默认开着）

方案的主翻译器没有写 =enable_user_dict=，librime 默认即为 =true=，所以**用着用着会自己变**：

- **调频**：你选过的候选下次会往前排
- **造词**：上屏的字词组合会被记进用户词典，下次能整串打出来

数据存在 =rime_ice.userdb/=（二进制 LevelDB，不进 git）。

**不参与学习的**（上游有意关掉，避免污染）：

| 翻译器                | 设置                     |
|-----------------------+--------------------------|
| =melt_eng= 英文       | =enable_user_dict: false= |
| =radical_lookup= 部件拆字 | =enable_user_dict: false= |
| =custom_phrase= 自定义短语 | =db_class: stabledb=（只读） |
| =cn_en= 中英混合词汇  | =db_class: stabledb=（只读） |

**万象语法模型不学习** —— =.gram= 是静态文件，不随使用变化。它管「句子结构是否合理」，
用户词典管「你个人偏好」，两者叠加生效。

*** 学错了怎么撤销
候选高亮时按 **=Ctrl+Delete=**（=editor/bindings= 里的 =delete_candidate=，删除或降权候选项）。
这是唯一的内置反悔手段。想要更强的（无视编码强制删词、把词降到第 4 位而不是删掉），
需要挂上游自带但本仓库没拿的 =lua/cold_word_drop/=。

*** 两个前端各学各的，靠 sync 合并
Squirrel 和 emacs-rime 是两个独立的 Rime 实例，各有各的 =rime_ice.userdb/=，本身互不相通。
本机已配置 Rime 自带的同步把两边合并，同步目录设在 Dropbox：

: /Users/lakki/Library/CloudStorage/Dropbox/RimeSync/

**同步机制**（=librime/src/rime/lever/user_dict_manager.cc=）：每个实例把自己的用户词典
全量导出到 =<sync_dir>/<installation_id>/<词典名>.userdb.txt=；同步时遍历 =sync_dir= 下
**所有**子目录，把找到的每个快照 merge 进本地库，然后再全量导出一次。
源码里**没有「跳过自己的目录」的逻辑**，所以是「先合并、再导出合并后的全集」，会收敛。

**配置**（写在各自的 =installation.yaml=，该文件不进 git，换机器要手工重做）：

| 实例       | =installation_id= | 位置                            |
|------------+-------------------+---------------------------------|
| 鼠须管     | =squirrel-macmini= | =~/Library/Rime/installation.yaml= |
| emacs-rime | =emacs-macmini=    | =~/.emacs.d/rime/installation.yaml= |

两边都加上：

#+begin_src yaml
installation_id: "squirrel-macmini"   # emacs 侧写 emacs-macmini
sync_dir: "/Users/lakki/Library/CloudStorage/Dropbox/RimeSync"
#+end_src

=installation_id= 只在**为空时**才由 librime 自动生成，写死之后就一直沿用，不会被重新部署冲掉。

★ **两边的 ID 必须不同。** 相同也能同步（见上面的机制），但会有两个坏处：
两个进程写 Dropbox 里同一个文件路径 → 产生「冲突副本」；只有一份快照 →
哪边的 userdb 被重置，它导出的小集合就直接盖掉那份唯一快照，另一边的数据没有备份。

**触发同步**：

- 鼠须管：菜单「同步用户数据」，或 =Squirrel --sync=
- emacs-rime：=M-x rime-sync=

⚠️ 改完 =installation.yaml= 必须**先重新部署**（=Squirrel --reload= / 重启 Emacs）才会读到新值 ——
=installation_id= 和 =sync_dir= 是部署期任务 =InstallationUpdate= 读的，单跑 =--sync= 不会重读。

*** 同步目录里还会有什么
部署时的 =BackupConfigFiles= 任务会把**用户目录顶层**的 =.yaml= / =.txt= 一并备份过去
（不递归，所以 =cn_dicts/= 那 44 MB 不会进 Dropbox；生成的 build 产物会被跳过）。
当前是 15 个文件，其中最大的是 =radical_pinyin.dict.yaml= 2.1 MB。有校验和比对，
没变的文件不会重复上传。

=~/.emacs.d/lisp/init-chinese.el= 里

#+begin_src elisp
rime-translate-keybindings '("C-f" "C-b" "C-n" "C-p" "C-g" "C-v" "M-v")
#+end_src

只有列在这里的按键才会被交给 librime，其余仍由 Emacs 自己处理。想让 =C-a= / =C-e= /
=C-d= / =C-k= / =C-h= / =C-y= 在候选栏里也生效，就往这个列表里加。

⚠️ **，。翻页的两条规则是不对称的**（出厂 =paging_with_comma_period= 组的原样）：

- 逗号 =when: paging= —— 只有**已经翻过页**之后才回上一页；停在第一页时逗号照常上屏「，」
- 句号 =when: has_menu= —— 只要候选栏开着就一律翻页，**打字过程中句号无法直接上屏**。
  正常写法是先上屏词、候选栏关掉，再打「。」，跟搜狗/微信输入法的默认行为一致

⚠️ **=Ctrl+V= / =Ctrl+Y= / =Alt+V= 翻页在部分 app 里不可靠。** 已确认 Chrome 地址栏中
第二次按 =Ctrl+V= 会穿透成粘贴。Rime 侧的配置和 librime 1.13.0 的
=KeyBinder= / =Selector::NextPage= 都验证过是会吞掉按键的，问题出在 app 的事件转发，
Rime 无从干预。**日常翻页用 =，。=，别依赖 Ctrl+V。**

出厂 =default.yaml= 默认启用的 =-= ~=~ 翻页（=paging_with_minus_equal=）本仓库**刻意没引** ——
=，。= 已经够用，而占着 =-= ~=~ 会导致候选栏开着时打不出这两个字符（如 =2-3=、=a=b=）。

⚠️ =Ctrl+K= 送出的是 =Shift+Delete=（出厂 =emacs_editing= 组的原样），但本方案的
=editor/bindings= 里**没有 =Shift+Delete= 这个绑定**（见下表），所以它大概率不产生任何动作。
真正的「删词」是 =Ctrl+Delete=。

⚠️ 同理，**=Tab= 在 Emacs 里不是「原始编码上屏」**。=init-chinese.el= 里有

#+begin_src elisp
(define-key rime-active-mode-map [tab] 'rime-inline-ascii)
#+end_src

elisp 层先截走了 Tab 用作「切行内临时英文」，librime 的 =Tab → Return= 补丁在 Emacs 内
根本收不到这个键。鼠须管里则是本仓库定义的行为。
